   - **업로드 UI 변경**: ` page.tsx `에 📜대본 / 📚자료 선택용 탭 및 리스트 섹션 구분 UI 추가
   - **GCS 폴더 분리**: `scripts/`와 `references/` 하위 폴더를 생성하여 파일 유형에 따라 독립적인 경로에 저장되도록 파이프라인 변경 (`ingest/route.ts`)
   - **문서 목록 조회 개선**: GCS 경로를 기반으로 자동으로 문서 유형을 식별하고 프론트엔드에 `docType` 반환 로직 추가 (`documents/route.ts`)

3. **인텐트(Intent) 라우팅 세분화 및 AI 프롬프트 특화 (핵심 기능)**
   - 인텐트를 기존 3개에서 5개로 확장 (`analyze_script`, `analyze_reference` 추가)
   - 질문의 키워드("대본", "1부", "자료" 등)에 따라 질문 의도를 분리 파악하도록 라우터 프롬프트 작성 (`chat/route.ts`)
   - **분리형 RAG 체인 구축**: 대본 분석 시엔 `script` 문서 컨텍스트만, 자료 분석 시엔 `reference` 문서 컨텍스트만 검색하도록 `docTypeFilter` 엔진 적용
   - 대본 전용(서사구조/캐릭터 아크/대사 분석) 프롬프트와 자료 전용(내용 요약 및 발췌) 프롬프트 분기 생성

### 🔴 주요 수정 요청 사항 및 피드백 반영 리포트 (강조)
- **업로드된 대본 파일(1부~4부)의 자동 호환 문제 해결**: 새로 추가된 하위 폴더 체계(`scripts/`) 이전에 루트 폴더에 업로드된 기존 대본 파일들이 있었습니다. 이러한 **기존 블랙위도우 대본 파일들이 인덱스 재구축 없이도 정상 작동하도록 "하위 폴더에 속하지 않은 파일은 모두 'script'(대본)로 예외 자동 분류"하는 소프트 마이그레이션 로직을 구축**하여 안정성과 유연성을 확보했습니다.
- **RAG 컨텍스트 분리 최적화**: 단순 검색을 넘어 대본과 자료 검색을 완전히 분리해 달라는 요청에 따라, 프론트-업로드-저장-검색 파이프라인 전 과정에 걸쳐 `docType` 아키텍처를 관통하도록 설계 범위를 대폭 확대하여 완벽히 분리 적용했습니다.
