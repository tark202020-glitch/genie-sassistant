# 지작(JIZAK) 초고 수정 프로토콜 — 개발자용 명세 v0.2

*근거: 『요리는 잘 하는 사람』 1고 1부(2~73쪽)·2부(74~155쪽) 편집 작업 실측 (2026.9.23~28)*
*v0.1 대비 변경: 설계 원칙 P7 추가, 파이프라인에 단계 0.5(바이블 대조)·단계 7(설정 확정 대화) 신설, 데이터 모델 3종 추가(지식 상태·설정 항목·메모 종류), 규칙 R25~R34 추가, 물음표 5분류, 골드 데이터·지표 갱신. 변경 위치는 **[v0.2]**로 표시.*

## 0. 설계 원칙

| #             | 원칙                       | 구현 의미                                                                                                                                                     |
| ------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1            | **살릴 것을 먼저, 고칠 것은 그 다음** | 장점 추출이 결함 탐지보다 앞. 결함은 장점 없이 단독 반환되지 않는다                                                                                                                   |
| P2            | **근거는 원고 문장**            | 모든 항목은 `evidence[]`(위치+원문 인용) 필수                                                                                                                          |
| P3            | **청사진이지 설계도가 아니다**       | 지작은 대체 문장을 쓰지 않는다(교정 층위 제외). 편집자의 대체 문장은 데이터로 받는다(R29)                                                                                                    |
| P4            | **작가 대입 탐지가 핵심 가치**      | "이 문장의 감각이 인물의 것인가 작가의 것인가"                                                                                                                               |
| P5            | **물음표는 단정하지 않는다**        | 정보/설정/질문/제안/바이블 5분류 **[v0.2: 5분류]**                                                                                                                       |
| P6            | **판단은 사람이**              | 채택/기각 상태와 기각 이유 = 정정 로그                                                                                                                                   |
| **P7 [v0.2]** | **원고가 바이블에 우선한다**        | 바이블 결정과 원고가 다르면 먼저 편집자에게 보고하고, 편집자가 "작가의 선택 존중"을 택하면 이후 분석은 원고의 선택을 전제로 원고 안의 상충·공백만 본다. 바이블은 그 결과로 갱신된다. 근거: 0901 "치사성 제거" 결정 vs 1고 "죽습니다" — 편집자가 원고를 택함 |

## 1. 파이프라인

```
[0 입력] 원고 + 프로젝트 지식(바이블·설정집·이전 부 총정리) + 편집자 메모(선택)
   ↓
[0.5 바이블 대조] [v0.2] 원고가 바이블 결정과 갈라진 지점 목록 → 편집자 판단(원고 존중 / 바이블 존중) → 이후 단계의 전제 고정
   ↓
[1 구조화]  장면 분할, 인물·설정·타임라인·반복장치 + 인물별 지식 상태표 [v0.2]
   ↓
[2 문체 프로파일]  시점·시제·리듬·서술자 위트·초점 인물 교체 (부 단위 재실행 — 2부에서 초점 인물이 바뀜)
   ↓
[3 장점 추출]  형광 + 구조 장점 + 이전 부에서 심은 것의 격발 판정
   ↓
[4 결함 탐지]  R1~R34
   ↓
[5 물음표 분류]  정보/설정/질문/제안/바이블
   ↓
[6 업그레이드 방향]  A급 1~3건 + 후보안 + 설정집 diff + 이전 부 총정리 갱신 항목
   ↓
[7 설정 확정 대화] [v0.2] 편집자와 지작의 질의응답으로 설정 항목을 숫자·물건으로 닫는다 → 파생 문장 목록 생성
   ↓
[출력] 부 총정리 + 설정집 diff(확정치) + 이전 부 총정리 갱신 + 정정 로그 + 프로토콜 갱신 후보
```

### 1-1. 단계별 입출력

| 단계 | 입력 | 출력 | 실행 주체 |
|---|---|---|---|
| 0 | 원고, 프로젝트 지식, 메모 PDF | `manuscript`, `knowledge[]`, `memo_pages[]` | 시스템 |
| **0.5** | manuscript, knowledge(결정 로그) | `bible_divergences[]` + 편집자 판단 | LLM + 편집자 |
| 1 | manuscript | `scenes[]`, `characters[]`, `settings[]`, `timeline[]`, `devices[]`, **`knowledge_states[]`** | LLM |
| 2 | manuscript, scenes | `style_profile` (부별) | LLM |
| 3 | scenes, style_profile, knowledge, 이전 부 strengths | `strengths[]` (fired 판정 갱신 포함) | LLM (루브릭 S) |
| 4 | 3 산출물, knowledge_states, R | `issues[]` | LLM (루브릭 R) |
| 5 | issues(unresolved), knowledge, 원고 전체 | `questions[]` | LLM |
| 6 | 전부 | `directions[]`, `alternatives[]`, `setting_diff[]`, `prev_part_updates[]` | LLM + 편집자 |
| **7** | setting_diff([확인]·[설정] 항목) | `setting_items[]`(확정치), `derived_lines[]` | 편집자 ↔ LLM 대화 |
| 후처리 | 전부 | `feedback_doc`, `correction_log`, `protocol_delta` | 시스템 + 편집자 |

### 1-2. 편집자 메모가 있을 때
v0.1과 동일. **[v0.2 추가]** 판독 불확실 마크는 `confidence < 0.6`이면 문서 말미 '판독 불가 목록'으로 분리해 편집자 확인을 받는다(2부: 41건 중 8건). 추정 복원문은 `[판독?]` 접두.

### 1-3. 단계 7의 실제 흐름 (2부 실측) [v0.2]
편집자가 설정 항목 하나를 열면 지작이 원고 근거·현실 근거(도메인 사전, 웹 검색)·후보 수치를 내고, 편집자가 정하고, 지작이 파생 문장과 다른 설정과의 충돌을 즉시 계산한다. 2부에서 한 사슬:
가격(2주 380만) → 복용량(250mg) → 통(1주치 총알 크기, 2주 2통) → 반입(립스틱 케이스) → 온도(인슐린 모델: 냉장 장기, 실온 4주, 40°C 변색, 60°C 분해) → 계량(스푼 vs 저울) → 파생 문장 11개소(79·89·90·91·126·131 등) + 1부 갱신 2개소(S6 반입, 56쪽 반응 강도).
한 항목의 확정이 평균 3~4개의 원고 문장과 1~2개의 다른 설정 항목에 영향을 준다. 이 의존 그래프가 단계 7의 핵심 산출물이다.

## 2. 데이터 모델

### 2-1. 위치 — v0.1과 동일

### 2-2. 편집자 메모 마크 **[v0.2: `kind` 추가]**

```json
{
  "mark_id": "m-144-01",
  "loc": {...},
  "color": "red",
  "symbol": "none",
  "text": "아무래도 찬 음식이 맞나봐요.",
  "kind": "fix | line | question | bible | correction",
  "confidence": 0.9,
  "resolved_type": null
}
```
`kind` 규칙:
- `line` — 편집자가 쓴 대체 대사/문장. 지작은 원문과 나란히 놓고 **왜 나은지의 기제**를 붙인다(R29). 2부 16건
- `question` — 단계 5로
- `bible` — 해당 부의 수정이 아니라 작품 전체 설계에 관한 제안(2부: "강유리 남친이 치료제를 알려주는 사람이라면?"). 총정리가 아니라 바이블 갱신 큐로 보낸다
- `correction` — 교정(파랑)
- `fix` — 그 외 판단 메모

태그 사전 v3 유지. 2부에서 새 기호 없음.

### 2-3. 장점 — v0.1과 동일. **[v0.2]** `fired` 판정은 부마다 재실행한다. 1부 `planted`가 2부에서 `fired`로 바뀐 예: 39쪽 요리 기술=범죄 기술 → 90~92쪽 사과 소스. 2부에 새로 `planted`된 것: 85쪽 PHASE II, 94쪽 와인 미각.

### 2-5. 물음표 **[v0.2: 5분류]**

`type`: `info | setting | ask_author | propose | bible`
- `bible` — 원고 어느 부의 수정도 아닌, 설계 변경 제안. 총정리 §"큰 아이디어"로 분리 출력. 작가에게는 제안이 아니라 질문 형태로 간다("강유리의 남자친구는 누구입니까?")

2부 실측 분포: 원고 내 해결 3 / 설정 7 / 질문 5 / 제안 6 / 대사 교체(line) 16 / 판독 불가 8 / 바이블 1. 작가 전달은 설정 7 + 질문 5 + 제안 3 = 15건.

### 2-6. 문체 프로파일 — v0.1과 동일. **[v0.2]** 부 단위로 `focal_characters[]`를 기록한다. 2부: 이정은·윤현채·진영준·이사회·진명호. 초점 교체는 장면 단위 허용, 장면 내 교체는 R8 위반.

### 2-7. 정정 로그 — v0.1과 동일. **[v0.2]** `editor_decision`에 `disputed` 추가: 지작이 편집자 메모에 이견을 냈고 편집자 판단 대기(2부 4건: 월 1회→2주 1회, 미필적 고의 화자, 제목 문장 병치, 109쪽 서술 추가 불가).

### 3-6. 정보 설계 **[v0.2 신설]**

|---|---|---|---|---|

| R28a | 설정 대화에서 현실 근거는 원고 밖 통계·관행·실물 규격으로 댄다 | `reality_basis` 비어 있음 | 웹 검색·도메인 사전 | 마약 지출 통계, 금 시세, 인슐린 보관, 마이크로 스쿱 규격 |

| R32 | **인접 장면 중복은 보상이 있는 쪽을 남긴다.** 같은 정보를 나르는 두 장면이 붙어 있으면 관계·감정 보상이 있는 장면을 살리고 앞 장면은 반응만 남긴다(R10의 장면판) | 인접 장면 정보 집합 교집합 > 60% | 앞 장면 압축 | 이사회(94~98) vs 아버지(99~100) |
| R33 | **제목 문장 보호.** 제목·주제를 직접 담은 대사는 교체 대상이 아니라 병치 대상. 소비되면 뒤에 답하는 자리를 요구 | 제목 어휘와 겹치는 대사 | 편집자 대체안과 병치, 회수 위치 확보 | 154쪽 "무슨 요리를 그렇게 잘해요?" |
| R34 | **서술자는 중심 질문을 닫지 않는다.** 소설의 핵심 질문(편집 프레임)에 서술자가 결말 전에 답하는 문장은 삭제 | 편집 프레임 키워드 + 단정 서술 | 삭제, 질문으로 되돌림 | 155쪽 "전부 약 덕일 것이다" |

## 4. 프롬프트 체인 — v0.1에 추가

**단계 0.5 바이블 대조 [v0.2]** — 입력: 결정 로그(날짜·항목·결론), 원고. 출력: `bible_divergences[{item, bible_decision, manuscript_state, evidence[]}]`. 편집자 선택지: `follow_manuscript | follow_bible | defer`. 선택 결과는 이후 모든 프롬프트의 시스템 지시에 고정 문장으로 주입("이 원고에서 포르티시모 급중단은 치사적이다").

**단계 1 구조화 [v0.2 확장]** — `knowledge_states` 생성 프롬프트: 주요 인물 3~5명에 대해 장면마다 "이 장면 끝에서 X가 아는 것 / 믿는 것 / 모르는 것"을 원문 근거와 함께 기록. 이전 장면 상태를 입력으로 넣어 전이만 쓰게 한다.

**단계 4 결함 [v0.2 확장]** — 실행 순서: R26 → R25 → R17·R18·R8 → R30 → 나머지. R25는 `knowledge_states` 없이 실행하지 않는다.

**단계 6 방향 [v0.2 확장]** — `prev_part_updates[]`: 이전 부 총정리의 §후보안·§작가 확인·§복선표 중 이번 부가 답하거나 뒤집은 항목. 2부 예: 후보안 A 지지, 진영준 '저' 확정, 82쪽 오기→153쪽.

**단계 7 설정 확정 대화 [v0.2 신설]** — 턴 구조: (편집자 항목 제기) → 지작: 원고 근거 + 현실 근거 + 후보 수치 2~3개 + 각 수치의 파생 영향 → (편집자 확정) → 지작: `setting_item` 갱신 + `derived_lines` + `affects` + 이전 부 갱신 항목. 편집자가 수치를 바꾸면(예: 15mg→25mg→250mg, 380만) 표만 재계산하고 서술은 반복하지 않는다.
